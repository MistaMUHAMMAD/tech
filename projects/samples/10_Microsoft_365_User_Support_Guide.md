# Microsoft 365 user support guide

Portfolio Sample | Muhammad Musa | October 2026

Demonstration template. No employer records or real user data.

## Purpose

First-line support checks for a user-facing problem. Administration changes require the appropriate role and approval.

## Capture the issue

Record the affected application, sign-in account type, device, start time, error text and whether other users are affected. Never ask a user to disclose a password or MFA code.

## Sign-in

1. Confirm the expected work/school account and that the device has internet access.
2. Record the error code and time. Distinguish one application from a wider sign-in issue.
3. Check whether the user can reach the service in a supported browser.
4. If authorised, check service health and relevant account/licence status.
5. Escalate persistent errors with the time, error code, affected application and completed checks. MFA or policy changes belong with the authorised administrator.

## Outlook or email

Check the reported symptom: connection, sending, receiving, repeated sign-in or one message. Compare browser access with the desktop application. Record any delivery-report code and use the current Microsoft troubleshooting resources. Do not delete a profile or data without an approved recovery plan.

## File access or sync

Confirm the correct account, file location, permission owner and whether access works in the browser. Record any sync status/error and available device storage. Escalate permission changes through the approved owner. Do not make confidential content public to bypass access problems.
